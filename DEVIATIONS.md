# DEVIATIONS.md

Every departure from the original specification, with reason and impact. Append-only.

| # | Specification item | Deviation | Reason | Impact |
| --- | --- | --- | --- | --- |
| V-001 | "Package management: `uv`" with `uv.lock` | Both `uv.lock` (from `uv lock`) and `requirements.lock.txt` (from `uv pip compile`, 105 pinned packages) are committed. | The project is installed as an editable package rather than a `uv` workspace project; shipping both lock artifacts makes pinning unambiguous for `uv` and non-`uv` users alike. | None on reproducibility. |
| V-002 | "Optional semantic retrieval: pinned local embedding model" | Interface + deterministic hash-embedding mock ship by default; `sentence-transformers` is an optional extra and is **not** exercised in the reported results. | Keeping CI free of a ~500 MB model download and of network access. | Reported retrieval numbers are lexical (BM25/FTS5). Recorded in every manifest. |
| V-003 | "Simulate process termination after event log append" | The interrupted-write fault is a *logical* abort inside a controlled write sequence, not a real `SIGKILL`. | A real kill cannot be driven deterministically in-process, and SQLite's own WAL recovery would be the thing under test rather than the memory layer. | Documented in DECISIONS D-002 and in threats to validity. |
| V-004 | LongMemEval integration | Adapter, checksum registry, category mapping, and smoke subset are implemented; **no benchmark data is committed** and no LongMemEval numbers are reported in this artifact state. | The dataset is not redistributable and was not available in this environment. | LongMemEval rows in the claims registry stay `pending` until a user supplies the download. |
| V-005 | "Paper format: LaTeX using an IEEE conference structure" + compile | The paper is written against `IEEEtran`; **no LaTeX engine is installed in this environment**, so `memcheck paper --build` is unavailable here and `--validate` is used instead. | `pdflatex`/`latexmk` absent on the development machine. | Source validation (balanced environments, resolvable `\input`s, defined citation keys, no unresolved placeholders in supported claims) runs in place of a compile. |
| V-006 | "Optional adapters for Mem0, Zep" | Not implemented. | Explicitly optional in the specification and each would add a network/service dependency that CI cannot satisfy. | The adapter interface (`MemoryBackend`) is the extension point; noted as future work. |
| V-007 | Default LLM provider for reported results | Reported results use the deterministic mock reader (`mock:oracle-reader-v1`), not a paid model. | No API credentials in this environment and `ALLOW_PAID_RUNS` is unset; the specification forbids paid runs without both controls. | Results measure memory-system behavior with a perfect reader (DECISIONS D-006). Paid-provider paths are implemented, cost-gated, and untested against a live endpoint. |
| V-008 | Result format Parquet | CSV is always written; Parquet is written additionally when `pyarrow` is installed. | `pyarrow` is an optional extra so CI stays light. | None; CSV is authoritative. |
| V-009 | "Disable network access where practical" for coding tasks | The sandbox strips proxy variables and provider credentials from the subprocess environment and runs only an allowlisted `python -m pytest` invocation with a timeout, but it does not use a network namespace or seccomp. | Portable network isolation is not available from pure Python across macOS and Linux. | Best-effort, not a security boundary. Model output never reaches a shell: only structured file edits confined to a temporary sandbox root are applied. Documented in `agents/coding_agent.py`. |
| V-010 | "Report median, mean, standard deviation, and confidence intervals" | Reported for continuous metrics (bootstrap CI) and rates (Wilson interval). Paired significance testing is now **used**: McNemar with Holm correction, within each checkpoint and each store size. | Conditions answer the same query set, so their per-query outcomes are paired; an unpaired test would overstate the evidence. The earlier position -- that three seeds under a deterministic reader could not support a test -- was right about *seeds* and wrong about *queries*, which are the unit that varies. | The discordant-pair count is printed with every verdict, since it is the comparison's real sample size. Supersedes the previous statement that no difference is described as significant. |
| V-011 | LaTeX figure and table generation | `fig8_success_vs_cost` is deliberately **not drawn**: every reported run used the free mock reader, so monetary cost is identically zero. `table3_fault_recovery` is rendered as `[RESULT PENDING]` for the RepoEvolutionBench group, which declares no faults. | Drawing a degenerate plot or an empty table would present an absence of data as a measurement. | The skip and its reason are recorded in `paper/generated/report_index.json` and printed by `memcheck report`. |
| V-012 | Real-model runs are reproducible | They are not bit-reproducible. Across two LongMemEval runs differing only in the guarded backend's write policy, the three baselines --- which have no write policy and were therefore unchanged --- moved on 0, 3, and 6 of 60 queries respectively. | Temperature is zero, but neither a reasoning model nor the LLM judge is deterministic. | Reported in the paper as the noise floor against which the guarded layer's 24-query shift is read, rather than presented as determinism. The configuration comment asserting the baselines "must reproduce exactly" was wrong and is corrected. |
| V-014 | "Failed and partial runs are reported, never dropped" | Two `partial` attempts at the 100-instance LLM-extraction configuration were **moved, unchanged and still checksummed, to `results/raw_partial/`**: `..._20261021T103002Z_bc11e1d5` (10 of 12 conditions; two guarded seeds failed on an extraction length stop, D-021; $2.43) and `..._20261021T141226Z_bc11e1d5` (9 of 12; all three guarded seeds refused by the provider with `429 insufficient_quota`, the account's credit balance having run out; $0.45). | The reporting layer pools every run in a comparability group; a partial run beside its complete re-run would have averaged the baselines twice and the guarded layer once. | Both runs remain inspectable and contribute to no reported number. Their cost is included in the paper's cost statement. The provider now fails fast on an exhausted balance instead of retrying. |
| V-015 | "Repetitions ≥3 per stochastic condition" | On LongMemEval the three seeds are replicas, not repetitions: outcomes were identical across seeds for every query in every run. Per-group `task_utility.csv` and `paired_comparisons.csv` still report $n$ as queries × seeds. | The benchmark is deterministic and identical requests are served from the per-run cache; the runner has no notion of a seed-insensitive workload. | The paper takes every LongMemEval $n$, interval, discordant count and $p$ from the write-policy analysis, which collapses replicas (D-022). Run-to-run variation is measured by re-running the unchanged baselines instead: between the two complete n=100 runs (2026-10-21 rule-based, 2026-10-22 LLM-extract), transcript chunking changed on 3 of 100 queries, full history and no memory on 0. |
| V-016 | "Sampled LLM-judge decisions should be human-audited" (challenge R3; DECISIONS D-014) | The audit was **not performed** before submission. `memcheck audit` exported stratified samples for both n=100 LongMemEval runs, plus blinded, shuffled copies (`audit_sample_blind.csv`, 45 and 51 rows) with the condition, judge label and rationale removed. | The user chose to submit without labelling (2026-10-28). | Stated in Threats to Validity; judged numbers carry the judge's error rate as an unmeasured term. The deterministic workloads (RQ2–RQ4) use no judge. Labelling the blind file and running `memcheck audit --agreement` remains possible at any time. |
| V-013 | "Optional adapters for Mem0, Zep" (revisited) | Still not implemented, and now the single largest gap. | 2026 work evaluates deployed systems directly; a study of four designs we wrote ourselves cannot speak to software people operate. | Recorded as the first item of future work in the conclusion, not as a limitation of the present claims, which are stated about the designs actually tested. |
| V-017 | Human audit of the LLM judge (supersedes V-016) | **Performed on 2026-10-28** by one author on the blinded sample of the rule-based n=100 run (`results/audit/longmemeval_v1_9f26e37d_openai_gpt-5-mini_rule_copula_v1_140bed/audit_sample.csv`, 51 rows). The first pass graded answers against the retrieved evidence because the README did not state the criterion; the 13 judge-decided rows that disagreed with the judge or were blank were re-checked against the gold answer (`audit_sample_recheck.csv`). Two re-check labels of `abstained` on questions the model had answered are treated as the rater declining to label. Result (`results/processed/audit/judge_agreement_*.json`): 47 labelled rows, observed agreement 0.66, $\kappa$ 0.51 overall; on the 28 rows the LLM judge itself decided, 18 agreements, 0.64, $\kappa$ 0.24. All ten disagreements are judge `incorrect` / rater `correct`: four short numeric answers differing from the gold value, six preference questions. The LLM-extract run's blind sample remains unlabelled. | The audit was the one item only a human could do; the labeller criterion ambiguity was ours (fixed in `audit.py`). | Reported in Threats to Validity as measured. The judge is stricter than the single rater in this sample; judged accuracies are, if anything, understated, and every condition was graded by the same judge. |
| V-018 | "Repetitions ≥3 per stochastic condition" (synthetic and repository workloads) | Every synthetic and repository run before 2026-11-03 replayed **one stream for all seeds**: `build_workload` used `config.seeds[0]` and the runner reused it. All n, intervals, discordant counts and p-values in those runs were inflated threefold. The v1 generator also graded each current-value fact twice at the final checkpoint (`_cur` and `_xs`, identical requests). | A code bug, found by an independent audit (2026-11-03); D-022's statement that synthetic seeds differ was false. | The runner now builds one stream per seed for seed-sensitive workloads; synthetic v2 drops `_xs`; reports collapse seeds that reproduce each other exactly and say so. All synthetic and repository runs were re-run with v2 and ten seeds fixed in advance (D-024). The v1 runs are kept, unchanged and checksummed, in `results/raw_superseded/` and feed no reported number. Corrected, the draft's "ranking inversion" at 8–16 sessions is a non-significant point estimate, and the tombstone ablation does separate at 64 sessions. |
| V-019 | Evidence-budget contract | The contract's scenario sentences produced an empty fact key, so the rule-based extractor wrote nothing and the guarded store stayed empty; the contract passed without exercising the budget, and missed the no-budget ablation. | Scenario bug, found by the same audit. | Scenario fixed; every contract now checks its precondition and reports `vacuous` instead of `passed` when it fails; every contract has a seeded-defect test it must fail (`tests/unit/test_contract_mutants.py`). The budget contract now fails on the no-budget ablation in every run. |
| V-020 | LongMemEval judge and reader temperature | The judge was a single generic prompt (`judge_v1`) run on the reader model, not LongMemEval's per-question-type prompts. The configured temperature 0 was never sent: the provider skipped falsy values, and gpt-5-mini accepts only its default (1). | Departure from the benchmark's own protocol; provider bug. | Both n=100 runs re-graded offline with the official prompts (pinned commit d6dc8b5, verified verbatim) on gpt-4o-2024-08-06 at temperature 0 (`memcheck rejudge`, $0.27), into new run directories `*_rejudged_lme`; the source runs are untouched. The official judge is primary (D-025); the original pair is kept in `results/processed/write_policy_judge_v1/`. Judges agree on 181/193 distinct pairs (κ 0.83). The provider now sends the configured temperature to every model that accepts one, including 0. The paper states that gpt-5-mini ran at its default temperature. |
| V-021 | Human audit of the judge (supersedes V-017) | The V-017 audit is superseded. Its sample showed the rater the retrieved evidence, balanced the sample on the judge's own label (forcing its marginals to one half), and counted seed replicas twice; 4 of its 10 disagreements were rater errors against the gold. | Audit design faults. | A new blinded sample of 60 distinct (question, answer) pairs, 12 per question type, with the official criterion per row and no evidence or judge labels, is in `results/audit/lme_official_v1/` (D-027). Labelling by one author is pending; the paper marks the result `[RESULT PENDING]` until `memcheck audit --lme-agreement` is run. |
| V-022 | Table 9 cost | USD summed estimated cost over all three seeds, counting cache hits, and included grading calls. | Accounting error. | Reported cost is now billed spend: uncached calls only, grading excluded and reported separately. Guarded (LLM extraction) $1.95 vs. transcript $0.09. |
| V-023 | "Interaction streams should be replayed chronologically and evaluated at fixed checkpoints as the store grows" (challenge R3) and "store size is the only changing variable" (RQ1) | The reported size sweep compares five separately generated streams at their final size; within a run, v2 asks almost every query only at the full store, so the intermediate checkpoints carried storage and latency but no accuracy. Two additions on 2026-11-04, both free (reference reader): (1) workload **v3** derives one query set per checkpoint from the events delivered by that checkpoint (`asked_at_fraction`; checkpoints snapped to session ends), and `configs/longitudinal_v3_064.yaml` replays one 64-session stream per seed (same ten seeds and densities as the sweep) read at 8, 16, 24, 40 and 64 sessions: run `longitudinal_v3_064_20261104T112140Z_c16fc10e`, `results/processed/longitudinal/`. (2) A padding control, `configs/padding/*.yaml`: a fixed 8-session fact stream and query set with 0, 8, 16, 32 or 56 sessions appended that assert nothing, either naming queried attributes without a value ("topical", like the stream's own distractors) or sharing no content token with any fact ("unrelated"); runs `padding_v3_{topical,unrelated}_{000,008,016,032,056}_20261104T1122*`, `results/processed/padding/gap_by_padding.csv`. v3 generates the fact stream exactly as v2 does (pinned by test), so its final checkpoint reproduces the sweep's 64-session point to the query. | The sweep answers "does the verdict depend on the size at which you evaluate"; it does not show one store ageing, and because the attribute pool is fixed, "size" in it means deeper update and deletion history on the same facts, not more unrelated history. | Within one growing store the transcript-minus-guarded verdict moves from transcript ahead at 8 and 16 sessions (−0.039 [−0.060, −0.022] and −0.020, no deletions have occurred yet because the generator starts deletions at `sessions // 3`) through parity at 24 (+0.022) to the sweep's values at 40 (+0.128) and 64 (+0.279, identical to the sweep). Padding does not move transcript chunking at all (0.911 at every level, both styles) and moves the guarded store by at most −0.02 under topical padding, so the sweep's gap is caused by accumulated updates and deletions on the queried facts, not by store size as such. The paper must say so. The v2 sweep and matrix are unchanged and remain the primary evidence. |
| V-024 | "Gold labels come from the generator's own state, so they are exact" (synthetic workload, v2/v3) | Two generator defects, found while building v3 (D-028), corrected as workload **v4** on 2026-11-04; v2 and v3 stay byte-identical (pinned digests). (1) After a contradiction, the next update or re-assertion of that key read the history's marker entry as the current value, so re-assertions emitted a fact whose value is the literal `__contradiction__` (10 seeds pooled: 13, 92, 189, 460 and 816 events at 8, 16, 24, 40 and 64 sessions). v4 reads the last real assertion instead; this adds no random draw, so the stream is unchanged up to the first such event. (2) A temporal query's gold was the assertion just before the last one, which is often a re-assertion of the current value, so its gold equalled the current value (32 of 123, 99 of 253, 171 of 351, 228 of 370 and 191 of 332 temporal queries). v4 takes the value current just before the latest change of value, at an instant between that value's assertion and the change, and asks no temporal query where no such instant exists (same-timestamp change, or a contradiction at that timestamp). Configs `configs/scale_v4/scale_v4_{008..064}.yaml` and `configs/experiment_matrix_v4.yaml` differ from their v2 sources only in name and version; runs `scale_v4_{008,016,024,040,064}_20261104T1154*`/`T1155*` and `experiment_matrix_v4_20261104T115543Z_e931c4ed`; comparison `scripts/v4_robustness.py` → `results/processed/v4/`. | The v2 query set grades degenerate temporal questions and a handful of marker-valued golds, so part of the reported guarded-store advantage could rest on them. | Matrix: identical contract violations per suite run, vacuous counts and fault recovery for every condition. Ablations: no verdict changes; first separation stays 24 (supersession) and 64 (tombstones). Transcript chunking changes: v4 gap (guarded minus transcript) −0.007, −0.035, +0.015, +0.134, +0.260 at 8–64 sessions against v2's +0.007, −0.005, +0.056, +0.157, +0.279. At 16 sessions transcript chunking is significantly ahead under v4 (Holm p 0.016, sign-flip p 0.035, cluster interval [−0.058, −0.010]); at 24 the v2 separation does not survive (Holm p 0.27, sign-flip p 0.078); from 40 the guarded store leads under both. The v2 statement "inseparable at 8 and 16, separated from 24" is therefore not robust to the corrected labels. |
| V-025 | Primary synthetic evidence (all synthetic tables, Fig. 2, the longitudinal run, the padding control, the aged-store contracts) | On 2026-11-04 the paper's primary synthetic evidence moved from the v2/v3 labels to the corrected labels: workload v4 for the size sweep (`scale_v4_*_20261104T1154*`/`T1155*`) and the 40-session matrix (`experiment_matrix_v4_20261104T115543Z_e931c4ed`), and a new workload **v5** (v3's checkpoint-relative queries and padding with v4's two fixes; v2, v3 and v4 byte-identical, checked against the previous code) for the longitudinal run (`longitudinal_v5_064_20261104T122046Z_3d66d637`) and the padding control (`padding_v5_{topical,unrelated}_{000,008,016,032,056}_20261104T1221*`/`T1222*`).
